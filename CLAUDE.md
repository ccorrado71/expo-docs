# CLAUDE.md

User documentation of **EXPO** (crystal structure solution from powder diffraction
data, IC-CNR Bari), built with MkDocs + Material and published on GitHub Pages at
<https://ccorrado71.github.io/expo-docs/>. A PDF manual is generated from the same
sources with pandoc.

The documentation is in **English**; conversations with the user are in Italian.

## Related repositories and sources

- `~/expo2`: EXPO source code (Qt6/C++ GUI + Fortran core). Use it to **verify every
  statement** of the documentation (menus in `src/*.ui`, directive parsers, defaults).
  Useful places:
  - command table: `src/commands.f90` (`allcom`), dispatcher in `src/expo2015.F90`
  - `%data` directives: `src/data2013.F90`; DM directives: `src/extra.f`, `norm.f`,
    `patter.f`, `invar.f`, `phase.f`, `four.f`, `poly.f`
  - `%sanneal` directives: `src/sannel.F90` (`read_dir_sa`), model/fragment
    directives: `src/gen_form.F90` (`read_dir_frag`); `%rietveld`: `src/rietveld.f90`
  - keyword matching: `word_is_contained` (min 4 chars, the abbreviation must be a
    prefix of the keyword, never longer)
  - Help/About links and update check: `src/mainwindow.cpp` (`openHelp`,
    `actionCheckForUpdatesTriggered`)
- `~/qualx3`: sister project (QualX) with the same MkDocs/pandoc setup; reference for
  conventions.
- Old documentation (WordPress): `https://www.ba.ic.cnr.it/softwareic/expo/`, reachable
  only through the CNR VPN. Pages are migrated from there: fetch with `curl`, extract
  text and tables, and re-check everything against the code (the old pages are often
  outdated: EXPO2014 names, old menus, wrong defaults, typos in formulas).

## Layout

```
docs/                    Markdown sources (one folder per multi-page section)
docs/images/<section>/   images of each section
docs/updates.json        GENERATED, read by EXPO's update check (do not edit by hand)
docs/download.md         GENERATED by scripts/make_download_page.py
docs/rietveld-theory.md, docs/superflip.md   drafts, not in nav (see below)
mkdocs.yml               nav, theme, markdown extensions
make_pdf.sh              PDF manual (pandoc + xelatex)
scripts/make_download_page.py   download page and updates.json from cnrbox links
```

`use_directory_urls: false`: pages are published as `page.html` (e.g. `indexing.html`,
`direct-space/index.html`). EXPO's Help buttons link to these paths, so **do not rename
or move published pages** without updating `~/expo2` (`openHelp` callers).

## Commands

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # once
.venv/bin/mkdocs serve           # preview at http://127.0.0.1:8000
.venv/bin/mkdocs build --strict  # must pass with no warnings; then rm -rf site
bash make_pdf.sh [out.pdf]       # default ./expo_manual.pdf (git-ignored)
```

The system `mkdocs` lacks the Material theme: always use the venv.

## Adding or moving a page

1. Add it to `nav` in `mkdocs.yml` **and** to `PAGES` in `make_pdf.sh` (same order).
2. If it lives in a new subfolder, add that folder to `--resource-path` in
   `make_pdf.sh`, otherwise its `../images/...` paths are not found by pandoc.
3. Link it from the related pages (cross-links are used extensively).
4. Run `mkdocs build --strict` and `bash make_pdf.sh`; check the PDF when the page has
   formulas or wide tables (`pdftoppm -f N -l N -r 60 -png expo_manual.pdf out`).

Draft pages: keep them out of `nav` and `make_pdf.sh`, list them under `not_in_nav`
in `mkdocs.yml`, add `search: exclude: true` front matter and a "Draft" admonition.

## Writing conventions

- Math with `$...$` and `$$...$$` (pymdownx.arithmatex, also understood by pandoc).
  Never leave formulas as images.
- Chemical formulas and subscripts with `~`: `C~10~H~16~N~6~S`, `*P*2~1~/*n*`
  (pymdownx.tilde).
- Definition lists (`def_list`) for options/fields; tables for directives
  (`| Directive | Description |`).
- Admonitions `!!! note` / `??? note`: `make_pdf.sh` converts them to block quotes.
- Inside table cells do not put `\|` within backticks (the backslash is shown);
  rephrase instead (e.g. `res_target_type type` and list the values).
- Input-file examples in ```` ```text ```` blocks, shell commands in ```` ```bash ````.
- Menu paths in bold with arrows: **Solve → Explore Trials**.
- References: `Author, A. B. (year). *Journal* **vol**, pages.` followed by
  `[doi:...](https://doi.org/...)`. **Verify every reference and DOI on Crossref**
  (`https://api.crossref.org/works?query.bibliographic=...`); do not write DOIs from
  memory. Percent-encode parentheses in DOI URLs (`%28`, `%29`).
- Images: re-use only screenshots that still match the current GUI; crop out desktop
  or personal content; prefer current icons from `~/expo2/src/pixmaps`.

## Download page and updates.json

`scripts/make_download_page.py` reads the packages in
`~/cnrbox/software/expo_packages` (ownCloud-synced), reuses or creates public read-only
links on cnrbox (credentials in `~/.netrc`, login `corrado.cuocci` + app password) and
writes `docs/download.md` and `docs/updates.json`.

- Use `--dry-run` to check without creating links. Creating public links publishes
  files: ask the user before running without `--dry-run` when new packages are present.
- `updates.json` is published at `https://ccorrado71.github.io/expo-docs/updates.json`.
  **This URL is compiled into EXPO and must never change.** Keys: `windows`, `linux`,
  `osx`, each with `latest-version`, `open-url`, `download-url`, `changelog`.

Release procedure: see "Releasing a new EXPO version" in `README.md` (packages → script
→ PDF copied into `~/expo2/share/expo/docs/expo_manual.pdf` → commit).
